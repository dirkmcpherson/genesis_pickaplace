# RNG / Seed Audit — 2026-08-17

Trigger: RLPD's demo buffer sampled with `th.Generator().manual_seed(0)` — hard-seeded,
ignoring `--seed` — so every "independent" RLPD seed consumed the identical demo-batch
curriculum (fixed in 2fbed2a). This audit sweeps every other randomness source in the
active training/eval code of the three repos and classifies each site.

Scope audited (read-only): `genesis_pickaplace/baselines/` (RLPD/SACfD trainers, envs,
eval stack, harvester), `~/workspace/r2dreamer/` (trainer, buffer, envs, evals),
`~/workspace/dreamerv3-torch/` (dreamer.py, tools.py, models.py, exploration.py, envs).
NOT audited: lerobot fork internals (DP/ACT *training*), Genesis solver internals
(its load-dependent nondeterminism is documented separately and is not an RNG issue).

Severity rubric: **CRITICAL** = correlates runs that claim independence, or invalidates
seed-identity/pairing claims. **MODERATE** = reproducibility only. **BENIGN** =
intentional fixed stream (with the reason it is fine).

---

## Ranked findings

### F1. CRITICAL (FIXED in 2fbed2a) — RLPD demo-sampling stream was hard-seeded 0
`baselines/rl/rlpd_sac.py:182` (current, fixed form):
```python
self._g = th.Generator().manual_seed(int(seed))
```
Before 2fbed2a this line was `th.Generator().manual_seed(0)`: every RLPD seed drew the
IDENTICAL demo-index sequence for the demo half of every batch. `seed` now comes from
`--seed` (`train_rlpd.py:275: demo = DemoData(..., seed=args.seed)`); `--seed 0`
reproduces the old stream exactly. Pre-fix multi-seed RLPD claims are already struck
in PAPER_PLAN (19eed7d). Status: closed; listed for the record.

### F2. CRITICAL — dv3 replay/demo minibatch sampling is hard-seeded 0 for EVERY run
`~/workspace/dreamerv3-torch/tools.py:495-496`:
```python
def sample_episodes(episodes, length, seed=0):
    np_random = np.random.RandomState(seed)
```
and the only call site never passes a seed — `dreamer.py:285`:
```python
generator = tools.sample_episodes(episodes, config.batch_length)
```
(same for `pretrain_dataset` at dreamer.py:581 and `train_dataset`/`eval_dataset` at
675-676). This is the **same bug class as F1, live in the dv3 arm**: every dv3 run —
regardless of its seed — draws episode choices and window start-indices from
`RandomState(0)`. Consequences:
- **Offline/pretrain/demo phases** (fixed episode set, e.g. demo prefill or
  `pretrain_eps`): the minibatch curriculum is bit-identical across all "independent"
  runs. Cross-run variance from data ordering is silently removed, exactly what F1 did
  to RLPD. Partial mitigation: model init / action noise still differ per run (see F3),
  so runs are not fully paired — but the demo-sampling axis of independence is dead.
- **Online phase**: the index stream is identical but operates on diverging episode
  sets, so the correlation decays with online data; the early-training window (buffer
  dominated by prefill demos) is the most correlated.
Any dv3 claim of the form "N independent seeds saw the demos in independent orders" is
not supported. H4 (world-model arm) statistics should disclose this.

### F3. CRITICAL (claims) / MODERATE (statistics) — dv3 ignores the configured seed entirely
`~/workspace/dreamerv3-torch/dreamer.py:395`:
```python
config.seed = np.random.randint(0, 2**31 - 1) # 4
```
This unconditionally overwrites `config.seed` with a draw from the **unseeded** numpy
global (OS entropy) before `tools.set_seed_everywhere(config.seed)` (line 396).
Introduced 91ff804 ("remove single seed", 2026-01-16). Effects:
- `--seed N` / `configs.yaml seed: 0` is dead code: every run gets a random effective
  seed. Runs labeled "seed 0/1/2" are NOT those seeds.
- Any **paired-seed design** involving dv3 (e.g. "same seeds across demo-source
  conditions") is fictional for the dv3 arm — pairs are random-vs-random. That
  invalidates paired statistics, hence CRITICAL under the rubric.
- `config.deterministic_run` cannot reproduce a run even in principle; there is no way
  to re-run a given dv3 run.
- It does NOT correlate runs (it anti-correlates them), and the effective seed IS
  recorded post-hoc (`run_config.json` dump and wandb `config`, both written after
  line 395) — so run identity is recoverable, but not re-runnable.
Note the interaction with F2: F3 randomizes model init while F2 freezes the
data-sampling stream — dv3 runs are "random weights, identical demo curriculum".

### F4. MODERATE — DP/diffusion evals sample from an UNSEEDED torch global (inverse class)
`baselines/wandb_eval.py` never calls `torch.manual_seed` (no seeding site anywhere in
the file or in `dp_runner.py`), and the DP path (`--kind dp`) runs
`DiffusionPolicy.select_action`, whose denoising loop draws Gaussian noise from the
torch global RNG. So every DP eval invocation is nondeterministic: re-running the same
checkpoint on the same ICs gives different rollouts. The SAC path is unaffected
(`model.predict(..., deterministic=True)`, wandb_eval.py:191/218). ACT is deterministic
at inference. Known-robust caveat: measured 15-episode pick RATES have proven stable
across protocol changes (memory: eval-episodes-not-independent), so this degrades exact
reproducibility, not headline rates. Fix if desired: `torch.manual_seed(args.seed)` at
wandb_eval startup.

### F5. LOW/MODERATE (design note) — random-IC eval sets differ per training seed
`baselines/wandb_eval.py:261-262`:
```python
_ic_sets['random'] = ic_sampling.sample_support_ics(env, args.random, seed=args.seed)
```
`VideoEvalCallback` passes the TRAINING seed (train_rlpd.py:343, wandb_utils.py:160),
so seed-0 and seed-1 runs are scored on *different* random-IC draws — cross-seed
comparisons of `eval_random/*` carry IC-set sampling variance on top of policy variance.
Not a correlation bug (and the headline demo-IC set `demo_ics` is RNG-free and identical
for everyone). If tighter cross-seed comparability is wanted, pin a shared eval seed
(e.g. constant 0) for the random-IC set — which is already what ad-hoc `wandb_eval`
invocations get via the `--seed` default of 0.

### F6. BENIGN-note — dv3 train and eval envs share the same env seeds
`dreamer.py:607-608`: `make("train", i)` and `make("eval", i)` both construct the env
with `seed=config.seed + id` (dreamer.py:363), so the eval env replays the same
uid-choice np_random stream as its train twin. Same distribution either way; no
independence claim rests on it.

## Inverse-class sweep (should-be-deterministic paths)

- **DP eval sampling unseeded** — F4 (the one real hit).
- Time-based seeds: none found in any scoped file (`grep 'seed.*time()'` clean).
- Set/dict iteration feeding sampling: none — every uid pool is `sorted(...)`
  (full_env.py:209/228/541, pick_env.py:86, genesis_can_env.py:153,
  genesis_vec_env.py:76, harvest uid_pool), dv3 `episodes` dicts are
  insertion-ordered from sorted file loads. `set()` uses (`_granted`, `resettable`)
  are membership/sum only — order-independent.
- Module-global `np.random.*` calls outside seeded contexts: only
  `dreamer.py:395` (F3). SB3's internal `np.random` use is behind its own seeding.
- Eval entry points that never seed torch: `wandb_eval.py` (F4);
  `genesis_eval.py` / `eval_genesis.py` / `eval_ms.py` do seed or run mode-only.

## Not audited (declared gaps)

- lerobot fork training internals (DP/ACT dataloader shuffling, diffusion training
  noise). Out of scope; lerobot seeds from its train config — worth a follow-up if
  DP seed-variance claims become load-bearing.
- Genesis solver determinism under machine load (documented 2026-07-20: borderline
  demos flip under 24-proc load) — environmental, not RNG; idle-box x3 protocol
  already covers it.
