Readings:
1. **The r2dreamer TRIGGER is present in dv3.** The task's maximum attainable return is 1.0 (one sparse +1, then
   terminate). In every ignited run the imagined λ-return targets run to 1.9–4.7 and the critic to 1.4–4.3 — the
   critic bootstraps through a terminal the model does not represent as terminal, exactly the mechanism §6 of
   `RESULTS_WM_HUMAN_VS_MACHINE_2026-09-04.md` names for r2dreamer (fixed there by `return_clamp = 1.0`).
   dv3's `reward_EMA` only rescales the ADVANTAGE by the 5–95 % percentile range (`max(range, 1)`); it does not
   remove the overestimate. dv3 already carries the lever: `models.py _compute_target` clamps the λ-return list
   when `return_clamp > 0` (08-28 flag, default 0; the tg_clamp list-clamp crash was fixed 08-28 §6).
2. **The r2dreamer AMPLIFIER is absent in dv3.** dv3's actor `dist: 'normal'` = `Normal(tanh(mean), std)` with
   `std = (max_std − min_std)·sigmoid(std + 2) + min_std`, `absmax None` (networks.py:713–720) — the same formula as
   r2dreamer's stock `bounded_normal` (distributions.py:217–221), not the `bounded_normal_clipped` projection that
   turned r2dreamer's entropy excursion into a permanent collapse. ⇒ the distribution half of H2 is moot; the entropy
   coefficient (dv3 stock 3e-4 vs r2dreamer's fix 3e-5) is the only H2 lever left. dv3 differs from r2dreamer in
   ways that are NOT levers in this ladder: actor gradient `dynamics` (backprop through the model) with the
   percentile-normalised advantage; critic `symlog_disc` + slow target.
3. Ignition is stochastic and separate from consolidation: 7 of the 8 R=0.25 runs ignited (first 25k bin ≥ 0.6 by
   40–70k env steps); fp16 s1 never did (entropy 9.93, zero online successes in 172k steps). A critic lever cannot
   help a run that never sees the reward.
4. Budget: 150k env steps ran 2:17–3:22 h (sacct, jobs 3242805–09 / 3244934–35; fps 14–21 on H200/A100); dv3
   divides `--steps` and `--time_limit` by `action_repeat` 4 (run_config: steps 37500 decisions, time_limit 300).
