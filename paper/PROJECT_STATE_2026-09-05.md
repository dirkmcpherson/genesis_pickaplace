## 1. What the project is

We have real recordings of a person driving a Kinova arm with a joystick to pick up a can, carry it onto a shelf, and slide it until it touches a second can that is already sitting there ("nested"). We rebuilt that scene in a physics simulator and spent weeks getting the simulator to replay those human recordings faithfully — the can starts where it really started, the arm moves the way it really moved, the pick, place and slide succeed or fail the way they really did.

The scientific question is about **where demonstrations come from**. Modern robot-learning methods lean on demonstrations. Human demonstrations are cheap to collect but messy: the person hesitates, idles, nudges the can, makes mistakes. Demonstrations generated by a trained policy are clean and consistent but need a policy first. The question we are answering: **when a learner uses demonstrations, does it matter whether they came from a person or from a machine?** We ask it for three kinds of learners, because the answer could reasonably differ between them:

- **Diffusion Policy (DP)** — pure imitation. It copies the demonstrations and never interacts with the world while training.
- **RLPD** — reinforcement learning that starts from the demonstrations and keeps practicing in the simulator.
- **World models** — the learner builds an internal simulator of the task from data, imagines rollouts inside it, and improves its policy on those imagined rollouts. Our main world model is a port called r2dreamer. A second port, dv3 (dreamerv3-torch), is being debugged so the world-model claim does not rest on one implementation.

## 2. The cast of characters

**Task stages.** *Pick* (lift the can), *place* (set it on the shelf), *contact* (slide it into the other can), *nested* (contact plus both cans upright and at rest). Each stage has a precise, code-level definition that has been through several audits.

**Demonstration sets.** All are recorded in the same corrected simulator world ("w3"), with the same recorder, at the same 7.5 decisions per second.
- **Human raw (dHv2raw)** — 66 human pick demonstrations exactly as driven, idling and all.
- **Human all-data (dHv2all)** — 106 tapes: the same 66 plus every human failure and no-pick tape. Built because a world model, in principle, can learn from failures too.
- **Human pruned (dHpruned)** — the raw set with the pre-pick idling cut out. Only DP uses it, because DP cannot cope with idling (it learns to sit still).
- **Machine (dDP)** — 58 demonstrations produced by a Diffusion Policy that was itself trained on the pruned human data, then run on the same 66 starting positions; it succeeded on 58. So "machine" here means clean, consistent, but ultimately distilled from the human data. That is a known limitation (see §7).
- For the later stages there are per-stage segment sets cut from full-task tapes (human) or from a full-task machine teacher's harvest, and for the end-to-end experiment there are full-length tapes: all 74 human tapes including the 10 that never picked, versus the machine teacher's best attempt at each of 72 starts.

**Evaluation sets.** *hold15* = 15 held-out human starting positions (in-distribution). *rnd30* and *rnd300* = 30 and 300 random can positions inside the box of human starts (out-of-distribution). For the later stages we cannot start "from scratch", so we start from **entry banks**: *holdE* = states taken from the human recordings at the moment the previous stage succeeded; *polE* = states generated by our own trained pick policies (148 of them); *polE-dDP* = the same made by the machine-trained pick policies; *polE_contact* = 160 placed-can states generated by the trained place policies (built today).

**How every number is produced.** The last checkpoint of each training run is loaded in a fresh process and run on the fixed evaluation set, both with sampled actions and with deterministic ("mode") actions. We compare arms with an exact permutation test on per-seed success counts, usually 8 seeds against 8 (4 against 4 for pilots). Every experiment is registered in a plan document with its prediction before it runs, and every mistake is written into the log the same day.

## 3. What has been established

### 3.1 The pick stage: no learner cares where the demonstrations came from

| learner | human demos | machine demos | difference | p |
|---|---|---|---|---|
| World model (r2dreamer), random starts | 0.617 | 0.608 | +0.01 | 0.88 |
| RLPD, random starts | 0.600 | 0.517 | +0.08 | 0.49 |
| DP (pruned human vs machine), random starts | 0.520 | 0.467 | +0.05 | 0.12 |

Plain reading: on the pick stage, with the demonstration counts matched, none of the three learners shows a demo-source effect, and if anything the direction favors the human demos. A retest on 300 random starts instead of 30 gave the same world-model answer (0.602 vs 0.618). One small wrinkle to be honest about: on the *training* starting positions the world model trained on human demos does slightly worse than the one trained on machine demos (statistically significant at the 0.04 level); out of distribution there is nothing.

### 3.2 Giving the world model the human failures did not help

The hypothesis was that a world model should benefit from failure tapes, because it learns dynamics from everything. Registered prediction: the all-data arm beats the raw arm. Result: it did not. World model 0.588 with all data vs 0.617 raw (p 0.58); RLPD 0.554 vs 0.600 (p 0.57). Neither learner gained from the failures, and neither was hurt significantly.

### 3.3 The clock is not hiding anything

Our learners decide once every four simulator steps. A diagnostic showed the machine demonstrations have high-frequency structure inside those four-step windows that the human ones lack, so I ran a pilot at one decision per simulator step, with everything physical held equal. Result today: human 0.642 vs machine 0.650 on random starts (p 1.0, 4 seeds each); every seed learned. The four-step hold was not masking an effect.

### 3.4 The place stage: still no difference, but the demo counts were not matched

Starting from the moment the pick succeeds, learn to set the can on the shelf. On the policy-generated starts: human 0.703 vs machine 0.709 (p 0.88); on the machine-generated starts 0.681 vs 0.720 (p 0.37). The caveat you raised this afternoon: the machine arm had 63 demonstrations to the human's 39. The extra demos can only have flattered the machine, but it is still not "same versus same", so a matched rerun with the machine cut to 39 is training tonight, and the matched number becomes the number of record. Also worth knowing: "placed" is granted anywhere on the shelf footprint, and the policies often set the can down at the far edge, well away from the goal can. The definition was registered in advance, but it means "place" measures reaching the shelf, not placing near the goal.

### 3.5 The contact stage: the easy bank saturates, a harder bank now exists

Starting from a placed can, learn to slide it into the goal can. On the bank of human placed states, every arm is at or near 100 percent — because in the human recordings the can was placed almost touching the goal, so contact takes one or two decisions. The human arm was trained on only 11 demonstrations (below the 20-demo floor we registered) and still learns this. To separate the arms I built a bank of 160 placed states generated by the trained place policies, whose placements are typically far from the goal. The first human seed scored on it lands at 0.475 in mode, so the bank does discriminate. The matched machine arm (also 11 demos) is training tonight; the one-armed 25-demo machine result stays as a descriptive row.

### 3.6 Carrycontact: the two-armed contact comparison

Because so few human tapes reach contact *after* releasing the can, the registered two-armed contact comparison starts from the pick-grant state and rewards contact by any route, held or released: 21 human segments vs 21 machine segments (matched today; the 36-demo machine version was cancelled before it started). Human seeds are landing at about 0.78 on the policy-generated bank; the machine seeds are training tonight.

### 3.7 End-to-end: learning the whole task from scratch

Your suggestion this morning. From the can on the table to nested, with the staged reward the RLPD arm used (1 for pick, 1 for place, 2 for contact, 4 for nested), 2 million steps, 4 seeds per arm, 74 human tapes including failures vs 72 best-per-start machine tapes. All eight runs are training; the first finish early tomorrow morning. Registered predictions: both arms learn the pick, no stage differs by more than 0.10, nested stays below 0.2 for both.

### 3.8 What the demonstrations actually look like

A quantitative side-by-side of the human and machine pick sets (72 paired starts): the human demos idle 45 percent of the time versus 4 percent for the machine, an enormous difference; when the human is moving they are actually faster; the approach geometry at the grasp is essentially identical; the human nudges the can before grasping more often. So the sets differ mostly in time structure, not in where the arm goes — which is a plausible reason the online learners are indifferent and pure imitation is sensitive to idling.

### 3.9 Second world model (dv3)

An agent has been debugging the dreamerv3-torch port all afternoon. It found the same failure trigger that broke r2dreamer: value targets running past the maximum attainable return of 1.0. With the return clamp ported, all four reach-proxy seeds have ignited and are holding at 1.0 during training. The gate is the fresh-process evaluation at the end of each run, due around 23:00 to 00:45. If it passes, the pick-from-demos pipeline is already built and tested for the next gate.

## 4. Where this sits in the literature (from the positioning note)

The closest precedent for a world-model demo-source result is a single figure in the MoDem paper, so we cite rather than claim first. Imitation's sensitivity to idle time is established. A controlled online RL-from-demonstrations comparison of human versus machine sources is, as far as we found, new. The recommended framing is that demonstration source matters far less for learners that interact with the environment than for pure imitation. The strongest reviewer objection is that our "machine" data is distilled from human data and the task is a single tuned one. The answer to both is the robomimic leg: the public Can task has human single-operator, human multi-operator and independently machine-generated (SAC rollouts) datasets. That plan is written and frozen, with verified dataset facts, gates and registered predictions; it costs about 220 GPU-hours and eight working days. Nothing is installed or submitted. ## 7. Caveats you should hold in mind when talking about the result

1. **Machine demos are a distillation of human demos**, not an independent generator. That is exactly what the robomimic leg addresses.
2. **One task, one simulator, state observations only** (no images). The world model reads the true can pose.
3. **The world model needed a modification to work at all** — a clamp on value targets at the maximum return. It is disclosed, it is the same for both arms, and dv3 now appears to need the identical fix.
4. **Demo counts** are matched at pick and end-to-end; the phase comparisons are being re-run matched tonight after your point this afternoon.
5. **The human all-data arm is unmatched by design** (106 vs 58); it tests a different hypothesis.
6. **The "place" definition** counts any shelf placement.
7. **A recorder change from the simulator-fidelity side** (a faster gripper release for human tapes) exists but is not used in any of these experiments; if it is adopted later, the machine arm must get the same treatment.

## 9. Small glossary

*Arm* — one experimental condition (a demo set × a learner). *Seed* — one independent training run. *Mode vs sample* — deterministic vs sampled actions at evaluation. *Prefill* — loading the demonstrations into the learner's replay buffer before training. *Return clamp* — capping the value targets at the maximum attainable return. *Entry bank* — a set of saved mid-task states used to start a later-stage episode. *Restore* — reconstructing such a state in the simulator. *Matched-N* — the machine set cut down to the same number of demonstrations as the human set. *Permutation test* — shuffling seed labels between the two arms to see how often a difference this large appears by chance.
