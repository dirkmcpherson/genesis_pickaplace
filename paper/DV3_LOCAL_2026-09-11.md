## 1. AUDIT: `model.rep_loss=dreamer` vs `r2dreamer` in this port

Read: `~/workspace/r2dreamer/dreamer.py`, `rssm.py`, `networks.py`, `distributions.py`,
`configs/model/_base_.yaml`. `rep_loss` is a `Dreamer.__init__` field (`dreamer.py:31`,
`self.rep_loss = str(config.rep_loss)`) read from `configs/model/_base_.yaml:19` (`rep_loss: "r2dreamer" #
r2dreamer/dreamer/infonce/dreamerpro`; set only via `model.rep_loss=<value>` on the command line — no env-group
override for it was found).

### What CHANGES between `rep_loss=r2dreamer` and `rep_loss=dreamer`

| Aspect | `rep_loss=r2dreamer` (default) | `rep_loss=dreamer` | file:line |
|---|---|---|---|
| Extra module | `self.prj = Projector(feat_size, embed_size)` + `barlow_lambd` | `self.decoder = MultiDecoder(config.decoder, ...)`; the `recon` loss-scale is broadcast onto every decoder key | `dreamer.py:102-116` |
| Representation-learning loss | Barlow-Twins-style cross-correlation between the projected posterior feature and the (detached) encoder embedding: `invariance_loss + barlow_lambd * redundancy_loss` | Reconstruction: `-dist.log_prob(data[key])` per decoder key. For `genesis_pick_state.yaml` (`decoder.mlp_keys='state'`, `cnn_keys='$^'`) this is symlog-MSE reconstruction of the 17-dim state only — confirmed live in the smoke: `Decoder MLP shapes: {'state': (17,)}`, `Decoder CNN shapes: {}` | `dreamer.py:423-438` (r2dreamer) vs `:418-422` (dreamer) |
| `video_pred` | `NotImplementedError` (no decoder) | Works | `dreamer.py:308-309` |

### What STAYS r2-specific (identical code path, unconditional on `rep_loss`)

All of the following run in the **shared** actor-critic / world-model code that executes identically for every
`rep_loss` value — none of it lives inside the `if self.rep_loss == ...` branches:

| Lever | What it does | Recipe value used here | file:line |
|---|---|---|---|
| `return_clamp` | Clamps the λ-return TARGET at a fixed max return, for both the imagination-rollout actor/critic loss and the replay-anchored value loss — the fix that stops the critic bootstrapping through an unmodelled terminal (`paper/DV3_DEBUG_2026-09-05.md` §1 point 1) | `1.0` (pick scope's true max return) | init `dreamer.py:41-48`; applied `:502-503` (imagination target) and `:552-553` (replay-anchored target) |
| `actor_dist` | Continuous-action distribution family: `bounded_normal` (tanh-bounds the MEAN only) or `bounded_normal_clipped` (samples projected into `[-1,1]`) | `bounded_normal` | config `configs/model/_base_.yaml:170-172`; impl `distributions.py:217`/`:236`; dispatched `networks.py:347` (built once at `dreamer.py:81`, outside any `rep_loss` branch) |
| `act_entropy` | Actor entropy-bonus coefficient | `3e-5` (vs dv3's dense-benchmark-tuned stock default `3e-4`) | init `dreamer.py:24`; applied `dreamer.py:512` |
| KL dyn/rep loss (world-model core) | Balanced dynamics/representation KL with free bits | `kl_free: 1.0` | `dreamer.py:412-414` via `rssm.kl_loss` (`rssm.py:222-230`), computed BEFORE any `rep_loss` branch |
| RSSM / encoder / critic architecture | deter/stoch/hidden/discrete sizes, `MultiEncoder`, `symexp_twohot` critic, slow-target update | shared | `dreamer.py:57-90` |

Naming collision to note: the KL loss's own `dyn`/`rep` split (`losses["rep"]`, `dreamer.py:414`) is unrelated to
the `config.rep_loss` STRING that picks among r2dreamer/dreamer/infonce/dreamerpro — the KL split exists
identically under all four.

### Verdict

**`rep_loss=dreamer` in this port is DreamerV3's stock representation-learning objective (reconstruction,
symlog-MSE on `state`) substituted into this port's own shared RSSM/actor-critic chassis — not a
byte-identical reproduction of upstream DreamerV3's full recipe.** The run inherits, unconditionally: this
project's own `return_clamp` fix (absent from upstream DreamerV3), the `actor_dist` config knob, and the
launch recipe's `act_entropy=3e-5` (not DreamerV3's dense-benchmark `3e-4`). So "stock DreamerV3 losses" is
accurate for the representation-learning term only; the actor-critic stabilization stack around it is this
port's own and is identical to what an `rep_loss=r2dreamer` run would use.

The **separate** `dv3_dbg`/`dv3_fix` tree that `paper/DV3_DEBUG_2026-09-05.md`'s G1/G2 ladder ran against is
`dreamerv3-torch`, a different codebase (no `rep_loss` switch). Its recipe values (`return_clamp 1.0`,
`delta_joint 0.025`/leash 5, `action_repeat 4`, batch 16x64, prefill 2500, pretrain 100, `reward_scale 1`,
`train_ratio 512`, `time_limit 1200`) are what this task reproduces *inside the r2dreamer port* as the closest
available G2-parity target, not a claim the two trees are the same code.

## 3. SMOKE

### Blocker chain hit and resolved along the way
Three real, sequential issues surfaced only by actually running the command (not caught by code reading):
1. **`tip_guard` cross-repo incompatibility** (PHASE_PLAN amendment (aa)): r2dreamer's adapter requires
   `env.tip_guard` and forwards it to `genesis_pickaplace.FullTaskEnv`; the tooling repo checkout did not have a
   matching parameter at the time this task started. Resolved when the amendment landed on
   `ladder-unify-2026-09-11` via a live merge during this session (`FullTaskEnv.__init__` now has
   `tip_guard='grip'` as its default). Config fix on the r2dreamer side: `genesis_pick_state.yaml` has no
   `ladder`/`tip_guard` keys, so Hydra needs the **add-key** form: `+env.tip_guard=grip`, not a plain
   `env.tip_guard=grip` override (confirmed: the plain form fails with `Could not override 'env.tip_guard' ...
   Key 'tip_guard' is not in struct`).
2. **Scope-oblivious `return_clamp` check ("D6"), found and disclosed by this lane, fixed by the coordinator.**
   `train.py`'s `_write_ladder_provenance` (landed with the same amendment-(aa)/Ladder-N merge) required
   `env.return_clamp == model.return_clamp == full_env.max_return(ladder)` for any genesis task, where `ladder`
   defaults to `'staged'` (max return `8.0`) whenever the env config doesn't set `env.ladder` — true for
   `genesis_pick_state.yaml`. But `genesis_pickaplace.FullTaskEnv` asserts `ladder == LADDER_DEFAULT or
   scope=='full'`, so `env.ladder=sparse` cannot be selected for `scope='pick'` either. Net effect:
   `return_clamp=1.0` (pick scope's TRUE max return — the episode terminates at the pick before any other ladder
   rung could ever fire) was refused with `FATAL: env.return_clamp=1.0 but ladder 'staged' has max return 8.0`.
   Reported to the coordinator rather than silently run under a scientifically-wrong `return_clamp=8.0` (which
   would have left the critic almost unclamped for a max-1.0 task — exactly the failure mode the clamp exists to
   prevent). **Fixed upstream: `full_env.max_return(ladder, scope)` / `ladder_provenance(..., scope=)` made
   scope-aware (every non-full scope pays one terminal +1, so the required clamp there is `1.0`); r2dreamer
   `train.py`'s D6 check now passes `env.scope` through. r2dreamer commit `5a40bbc`.**
3. **Silent no-op online-step window, found and disclosed by this lane, fixed by the coordinator.**
   `trainer.py`'s `OnlineTrainer.begin()` seeds its loop counter as `step = replay_buffer.count() *
   action_repeat` (trainer.py:137), i.e. MULTIPLIED by `action_repeat` (4), while `train.py`'s own preflight
   "Step accounting" assertion compares `config.steps` against the UNMULTIPLIED `replay_buffer.count()`. For this
   demo set (15564 transitions after prefill), the preflight only requires `env.steps > 15564`, but the loop's
   real starting counter is `15564*4 = 62256`. **Any `env.steps` in the dead zone `(15564, 62256]` passed the
   preflight and then hit `while step < self.steps` as immediately False — the entire online loop (env
   stepping, training, logging) never ran, no genesis world was ever built (no `[sim-variant]` line), yet the
   process still exited 0 and saved a checkpoint labeled with the configured step count** — indistinguishable
   from a real run except by checking for the `[sim-variant]` line or wall-clock (this lane's first "smoke" at
   `env.steps=20000` — squarely inside the dead zone — finished in **≈12 s wall clock**, versus ≈2 min just to
   build one world). Caught here before trusting it, by insisting on seeing the `[sim-variant]` line before
   reporting a pass. **Fixed upstream: the preflight now compares against the loop's real starting counter
   directly and refuses a budget inside the dead zone with an explicit message; it also prints prefill decisions
   and the counter start in env frames. r2dreamer commit `0cf3d9e`.**
