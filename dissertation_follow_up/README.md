# Dissertation follow-up: Diffusion Policy on the PushT and PinPad demonstration sets

Opened 2026-09-17. Goal: complete the demonstration-source comparison on the two 2024 benchmark tasks by adding the
three missing {Diffusion Policy} conditions, so each task carries the same agent × source grid as the can task.

Nothing here is started. This directory is a plan plus an inventory of what already exists; see
`INVENTORY_2024_RSS_RUNS.md` for the file-by-file record.

## 1. What is missing

Conditions are named `<agent>_<demonstration source>`; `Hu` = human recordings, `DfD` = generated by a trained DfD
agent, `DP` = generated by a trained {Diffusion Policy}.

| task | present | missing |
|---|---|---|
| PinPad-four | DfD_Hu, DfD_DfD, IBC_Hu, IBC_DfD, VMAIL_Hu, VMAIL_DfD — 8 seeds each | **DP_Hu, DP_DfD, DP_DP** |
| PushT | DfD_Hu, DfD_DfD, IBC_Hu, IBC_DfD — 5 seeds each (4 of record) | **DP_Hu, DP_DfD, DP_DP** |

A `DP_DP` arm also implies a {Diffusion Policy} teacher per task, which does not exist yet. If the dissertation only
needs human-versus-machine, `DP_DP` can be dropped and the teacher work with it.

## 2. Cost estimate (measured, not guessed)

Per-seed training, from our own lerobot {Diffusion Policy} runs of 100k updates at batch 64: about 6 h on a cluster
L40S with 64×64 images, about 3 h on state alone. Scaling to these tasks:

| task | image | frames per demonstration set | budget | per seed | seeds × conditions | GPU-hours |
|---|---|---|---|---|---|---|
| PushT | 94×94 | ~17 800 (100 episodes × ~178) | 100k updates | 6–8 h | 4 × 3 | 75–95 |
| PinPad-four | 64×64 | ~3 300 (13–15 episodes × ~251) | 30k updates (see below) | ~2 h | 8 × 3 | ~50 |

**PinPad needs a shorter budget.** 100k updates over 3 300 frames is roughly 2 000 passes over the data, which invites
severe overfitting. Plan: 30k updates with frequent checkpoints, and pick the budget from a checkpoint sweep on one
seed before launching the rest.

**Wall-clock on the cluster** at the 20-GPU per-user ceiling, ignoring other queued work: about 5 h for PushT and 3 h
for PinPad. On the pop-os workstation (one RTX 3080 Ti) the same work is about 4 days, so use the cluster.

## 3. Work before any training (about half a day)

1. **Converters.** The episode files are dreamer-style `.npz` (keys `image`/`pixels`, `state`, `action`, `reward`,
   `is_first`/`is_last`/`is_terminal`). A lerobot converter exists for the can task
   (`baselines/rl/to_lerobot*.py`, `convert_to_lerobot.py`); each task needs a small adapter for its own key names,
   action dimension (PushT 2, PinPad 5) and frame rate. Verify with the same gate we use here: episode count, frame
   count, and action bytes identical to the source tapes.
2. **`DP_DP` teachers** (only if that arm is kept). Train one {Diffusion Policy} per task on the human set, then
   harvest rollouts on the same starts, one attempt per start, keeping first attempts. About 8 GPU-hours plus a
   harvest, and it must finish before the `DP_DP` students start.
3. **Evaluation runners.** PushT and PinPad score differently from the can task. Rollouts are cheap in both, so
   scoring is minutes per seed. Reuse each task's existing evaluation path from the 2024 runs rather than writing new
   success predicates.

## 4. Metric trap to avoid (already hit once)

On PushT the two existing agents log different quantities under the same name: IBC's `train_return` is a per-episode
sum that reaches 704, while DfD's is a 0–1 value. **Use `original_reward` and `is_success`**, which both agents log on
the same scale, for any cross-agent figure. PinPad's `train_return` is comparable across agents as recorded. The 09-17
figures in `~/workspace/fastrl/analysis_2026-09-17/` follow this rule; the script there
(`plot_rss_returns.py`) takes `--key`.

## 6. Things to carry into the write-up

- **PinPad human arms were recorded in two batches.** IBC_Hu and VMAIL_Hu have seeds 5–7 from July 2024 and seeds 0–4
  from January 2025; every machine arm ran in 2024. Check one configuration from each batch before treating the human
  arms as one condition.
- **PushT has 5 seeds per condition** (imi20–24) where the design says 4. Decide which 4 are of record, by a rule that
  does not look at results, or report all 5.
- **Demonstration set sizes differ by source.** PinPad human sets hold 13–15 episodes, the DfD sets 15–20. Any
  source comparison at unequal quantity needs the quantity control the can-task work already uses.
- The can-task study's finding that {Diffusion Policy} tracks the success rate of its demonstrations predicts a large
  DP_DfD-over-DP_Hu gap on both tasks. State that prediction before running, so it is a test rather than a story.
